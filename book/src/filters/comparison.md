# Comparison

The three Kalman filters share the mechanization, the measurement models, the gating and the
initialization helpers (see [Kalman Filters](./kalman.md)). They differ in what they carry as
state and how they handle the nonlinearity.

| | [ESKF](./eskf.md) | [EKF](./ekf.md) | [UKF](./ukf.md) |
| --- | --- | --- | --- |
| `cl --filter` | `eskf` (default) | `ekf` | `ukf` |
| estimates | the error in a nominal trajectory | the full state | the full state |
| attitude | quaternion nominal, rotation-vector error, multiplicative correction | Euler angles, additive correction | Euler angles, perturbed, averaged and corrected on the rotation group |
| IMU biases | always (15 error states) | with `use_biases` (the default) | always through `initialize_ukf` |
| extra states | barometric bias only | map biases and barometric bias | map biases and barometric bias |
| nonlinearity | linearized about a nominal that is reset after every update | linearized about the current estimate (analytic Jacobians) | sigma points; no Jacobians in the filter |
| covariance update | Joseph form, then reset transport | Joseph form | $P - KSK^\top$, then reset transport |
| tuning beyond $P_0$, $q$ | none | none | $\alpha$, $\beta$, $\kappa$ |
| used by default in | `strapdown-sim cl`, `InsEngine` | | |

## When to use which

- **Start with the ESKF.** It is the default for structural reasons, not tuning: biases are
  always estimated, attitude is never linearized about Euler angles, and the error the filter
  linearizes is small by construction. It is the only filter `InsEngine` builds on its own. It has
  no geophysical implementation: `cl --geo` refuses it, and because it is the default, a
  geophysical run has to name `--filter ekf` or `--filter ukf`.
- **Use the EKF** for map-aided runs (the geophysical path runs the EKF or the UKF), when you need a
  nine-state filter, or when you want the textbook full-state formulation for comparison with
  published work. Its Jacobians are analytic and checked against the mechanization by
  `core/tests/jacobian_agreement.rs`.
- **Use the UKF** to study whether linearization matters for your scenario: it needs no
  Jacobians, so it is the reference against which a linearized filter's approximation shows
  up. Keep $\alpha$ at its 0.1 default unless you have measured otherwise
  ([why](./ukf.md#why-not-the-textbook-alpha-of-0001)).
- **Use the [RBPF](./rbpf.md)** when the measurement is a highly nonlinear or multimodal
  function of position, which is the map-matching case it was built for. It is a particle
  filter, run with `strapdown-sim pf`, and its configuration is separate.

## Accuracy

Accuracy is not asserted on this page. The numbers below are generated by
`core/tests/perf_baseline.rs`, which scores every filter over a fixed scenario matrix and fails
CI when a metric moves; `real_*` rows are a phone recording scored against its own GNSS track,
`syn_*` rows are synthetic and scored against exact truth. Read the
caveats on [Performance Baselines](../development/performance.md)
before drawing a conclusion from any row: on full-rate real-data rows, for example, every filter
is scored against fixes it has already been given.

No wall-clock comparison of the filters is published; nothing in the repository measures
runtime.

## Running all three on the same input

Every filter reads the same input and writes the same CSV columns, so a comparison is three runs
of `cl` that differ only in `--filter` (run here on a `syn` trajectory):

```bash
strapdown-sim syn -o synthetic.csv --duration-s 600 --seed 42
strapdown-sim cl -i synthetic.csv -o cl_eskf.csv --filter eskf
strapdown-sim cl -i synthetic.csv -o cl_ekf.csv  --filter ekf
strapdown-sim cl -i synthetic.csv -o cl_ukf.csv  --filter ukf
```

`strapdown-sim syn --no-noise` with the same flags writes the exact trajectory, and
[Tutorial: Particle Filter](../examples/tutorial-particle-filter.md#comparing-against-truth)
shows how to score an output CSV against it.

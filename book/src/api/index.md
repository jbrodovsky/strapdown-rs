# API Documentation

The complete API reference is the rustdoc generated from the source. This page maps the
workspace so you know which crate and module to open.

## Where to read it

| crate | imported as | rustdoc in this book | docs.rs |
|---|---|---|---|
| `strapdown-core` | `strapdown` | [api/strapdown](strapdown/index.html) | [docs.rs/strapdown-core](https://docs.rs/strapdown-core) |
| `strapdown-sim` | (binary) | [api/strapdown_sim](strapdown_sim/index.html) | -- |
| `strapdown-geonav` (experimental) | `geonav` | [api/geonav](geonav/index.html) | [docs.rs/strapdown-geonav](https://docs.rs/strapdown-geonav) |

The copy under `api/` is generated by `cargo doc` and published with this book, so it matches
the book's version of the code. The docs.rs pages appear once the crates are published to
crates.io with the v1.0.0 release; until then use the copy here or build your own.

To build and open the documentation locally:

```bash
cargo doc --workspace --no-deps --open                    # all three crates (alias: cargo docs)
cargo doc -p strapdown-core --all-features --no-deps --open   # include the hdf5/netcdf/mcap/clap items
```

Items behind a cargo feature only appear when that feature is enabled, which is why the second
command exists. Output goes to `target/doc/`, one directory per crate under its library name:
`strapdown`, `strapdown_sim` and `geonav`.

## `strapdown-core`

The library. Every module is public; `lib.rs` itself holds the 9-state strapdown mechanization
(`StrapdownState`, `forward`, the IMU input type) and the `NavigationFilter` trait.

| module | purpose |
|---|---|
| `alignment` | coarse alignment (Groves §5.6.3): roll and pitch by levelling, heading by gyrocompassing or from velocity |
| `calibration` | deterministic IMU calibration, removing systematic sensor errors ahead of the mechanization |
| `earth` | WGS84 ellipsoid constants, radii of curvature, normal gravity, Earth rate, transport rate, Eötvös correction, gravity anomaly |
| `engine` | `InsEngine`: a high-level, builder-configured navigation engine for feeding samples in one at a time |
| `error` | `StrapdownError`, the single error type every fallible function returns |
| `gating` | innovation gating (chi-squared outlier rejection) and its recovery policies |
| `kalman` | the Kalman-family filters: ESKF, EKF and UKF |
| `linalg` | linear-algebra helpers, chiefly robust covariance square roots |
| `linearize` | analytic Jacobians of the mechanization for the EKF and ESKF |
| `measurements` | the `MeasurementModel` trait and its models: GNSS position, velocity and both together, barometric relative altitude, magnetometer yaw, ZUPT and ZARU |
| `messages` | event-stream construction: GNSS, barometer and magnetometer scheduling and GNSS fault injection |
| `metrics` | navigation-accuracy metrics (RMSE, CEP, NEES, containment) for scoring a solution against a reference |
| `particle` | particle-filter building blocks: the `Particle` trait, resampling and averaging strategies |
| `rbpf` | the Rao-Blackwellized particle filter after Canciani & Raquet (2017) |
| `sim` | input records (`TestDataRecord`), output rows (`NavigationResult`), dead reckoning, the closed-loop runner, synthetic trajectories, configuration types and health monitoring |
| `stationary` | variance-based detection of stationary periods, for zero-velocity and zero-angular-rate aiding |

The crate root also re-exports `InsEngine` and its configuration types, `StrapdownError`, and
the gating types `InnovationGate`, `GateRecovery` and `UpdateOutcome`.

Its cargo features are all off by default, so `strapdown-core` alone needs nothing but a Rust
toolchain:

| feature | enables |
|---|---|
| `clap` | `clap` derives on the configuration enums, used by `strapdown-sim` |
| `hdf5` | `to_hdf5` / `from_hdf5` on `TestDataRecord` and `NavigationResult` (builds libhdf5 from source) |
| `netcdf` | `to_netcdf` / `from_netcdf` on the same two types (builds libnetcdf from source) |
| `mcap` | `to_mcap` / `from_mcap` on the same two types |
| `full` | all of the above |

## `strapdown-sim`

The command-line tool. It is a binary crate, so its rustdoc documents the program's internals
rather than an API to depend on; the user-facing reference is `strapdown-sim --help` and
[Running Simulations](../user-guide/simulations.md).

| module | purpose |
|---|---|
| `main` | argument parsing, the `dr`/`cl`/`pf`/`syn`/`ol`/`config` subcommands, and configuration-file runs |
| `common` | logging setup, input and output path validation (CSV output only), file discovery, interactive prompts |
| `plotting` | the optional `--plot` performance figure (feature `plotting`, on by default) |

Its `geonav` feature adds the `--geo` flags and depends on `strapdown-geonav`.

## `strapdown-geonav`

The experimental geophysical-navigation crate, a single module. Its main items are `GeoMap`
(NetCDF anomaly grids with interpolation and gradients), the measurement models
`GravityMeasurement`, `MagneticAnomalyMeasurement` and `CombinedGeophysicalMeasurement`, the
bias-state bookkeeping `GeoBiasLayout` and `BiasState`, and `build_event_stream`, which adds
geophysical measurements to core's event stream. See [Geophysical Navigation](../geonav/overview.md)
and [Maps and Measurement Models](../geonav/maps.md).
